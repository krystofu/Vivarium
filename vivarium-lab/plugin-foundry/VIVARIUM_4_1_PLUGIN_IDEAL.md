# VIVARIUM 4.1 Plugin Ideal

## Purpose

Vivarium plugins exist to make LoreBary roleplay more powerful, fun, immersive, stateful, surprising, and memorable. LoreBary is the authoritative runtime and deployment target. Vivarium does not optimize for abstract elegance or minimal prompt size; it optimizes for measurable improvement inside real LoreBary chats.

## The Vivarium Optimization

Vivarium does **not** treat small as automatically better.

**Earned scale beats arbitrary leanness.** A large plugin is desirable when every block, token, Agent, trigger, state field, table, switch, and instruction earns its cost through meaningful roleplay impact.

The core rule is:

> **Compress waste, not capability.**

Optimize for:

| Weak optimization target | Vivarium 4.1 optimization |
| --- | --- |
| Fewest tokens possible | Highest useful impact per token |
| Fewest blocks possible | Every block earns its existence |
| Tiny single-purpose prompt | Deep system when the system pays off |
| Lightweight for its own sake | Powerful without waste |
| Many tiny plugins | Fewer, broader, flagship-grade systems |
| Context minimization above all | Context efficiency without neutering capability |

## Six-Slot Economics

LoreBary exposes only **six plugin slots per roleplay**. Every slot is premium real estate.

A Vivarium plugin must justify consuming one of those six slots with a substantial experiential upgrade. Slot efficiency matters more than raw prompt brevity.

A plugin earns a slot by delivering a large, reliable improvement in one or more of these areas:

- fun, novelty, and payoff density
- immersion and scene continuity
- character initiative and autonomy
- persistent state and consequences
- relationship momentum and emotional continuity
- world motion and causal follow-through
- atmosphere, embodiment, and sensory presence
- strategic depth, tension, escalation, or transformation
- anti-repetition and long-session freshness
- compatibility with other flagship Vivarium systems

The ideal flagship plugin should feel closer to an **expansion pack** than a micro-feature.

## Power Standard

Vivarium 4.1 prefers plugins that are:

- **High impact:** the difference is obvious in live LoreBary play.
- **Stateful:** important truths survive beyond a single generation when LoreBary mechanics allow it.
- **Adaptive:** the plugin reacts to what actually happened rather than blindly forcing a preset pattern.
- **Causal:** effects arise from observed state, character motive, user action, or world conditions.
- **Composable:** the plugin can coexist with other major systems without duplicating ownership or causing prompt collision.
- **Persistent where useful:** consequences, motives, commitments, discoveries, and pressure can accumulate over time.
- **Expressive:** its machinery produces roleplay effects that are felt in scene, not merely tracked invisibly.
- **Inspectable:** large systems should still be understandable enough to debug, test, and repair.

## Block and Token Budget Rule

Vivarium does not impose a small default block count merely for tidiness.

A block earns its place when removing it causes a meaningful loss in:

1. roleplay fun,
2. immersion,
3. reliability,
4. state fidelity,
5. adaptive intelligence,
6. compatibility,
7. long-session quality, or
8. distinctive plugin identity.

If a block cannot demonstrate one of those benefits, it is a compression candidate.

If a 35- or 40-block plugin produces a dramatically better LoreBary experience and each component contributes, the size is justified.

## Architecture Ideal

The preferred systems pattern is:

**Sense → Interpret → Remember → Decide → Steer → Observe → Persist**

And the core doctrine remains:

**Use AI for meaning. Use state for truth. Use arbitration for salience. Use generation for expression.**

This avoids prompt piles and turns plugins into runtime systems.

## Flagship Standard

A flagship Vivarium plugin should create enough value that the user would notice its absence within a session.

Examples of the intended scale:

- VEIL should feel like a psychological strategy layer, not merely a covert-influence prompt.
- SPARK should create momentum, surprise, opportunity, reversals, and payoff rather than simply telling characters to take initiative.
- CHRONICLE should make long-form roleplay feel like a living campaign, not merely record plot facts.
- SOVEREIGN should reshape authority, pressure, adaptation, and relational power rather than just increase dominant tone.

## Certification Standard

Vivarium 4.1 plugins should be judged inside LoreBary through:

- Test Chamber mechanical/unit testing
- live single-plugin roleplay
- live multi-plugin stack testing
- long-session drift testing
- repetition testing
- state contradiction testing
- agency and boundary regression checks
- slot-impact evaluation
- context-cost versus experiential-gain review

A plugin is not successful because it is large. It is successful when its size is **earned**.

## Final Principle

> **A Vivarium plugin should spend aggressively when spending creates fun, immersion, intelligence, persistence, or impact. It should cut ruthlessly when spending creates only redundancy.**

That is the Vivarium 4.1 plugin ideal.
